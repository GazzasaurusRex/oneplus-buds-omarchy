## Further read-only investigation

### Touch assignments

- A diagnostic-only checkout profile sentinel enabled the raw `0x0108` touch
  query while supplying zero allowed functions; every returned control was
  serialized `writable=false` and no touch write was possible.
- The Pro 2 returned 14 bindings (seven per side).
- Current left and right button-1 mappings are identical: single tap (`1`) ->
  Play/Pause (`1`), double tap (`2`) -> Next track (`6`), triple tap (`3`) ->
  Previous track (`5`), Touch & hold (`4`) -> Switch noise control (`8`), and
  long hold (`6`) -> unlabelled wire function `18`.
- Each side also reports action `5` on buttons 2 and 3 mapped to None (`0`).
- This establishes read compatibility only. No functions or writes are enabled
  pending a phone-app change/read/restore trial.

Phone-app change trial:

- Changed only Left / Double tap from Next track to Previous track.
- Fresh raw read changed only the left `(side=1, button=1, action=2)` binding,
  from function `6` to function `5`; the other 13 bindings were unchanged.
- This confirms the side/action/function interpretation for that assignment.
- Phone restoration changed Left / Double tap back to Next track; a fresh read
  returned function `6` and the other 13 bindings remained unchanged.
- Only action `2` with functions `5` and `6` is now eligible for the isolated
  checkout write trial; every other touch mapping remains write-disabled.

Checkout plugin write trial:

- The profile exposed only Double tap -> Previous/Next; representative
  unconfirmed actions/functions were checked to reject without sending a write.
- Plugin changed Left / Double tap from Next (`6`) to Previous (`5`). Its own
  readback and a separately requested fresh touch read both returned `5`; all
  other bindings were unchanged.
- Plugin restored Left / Double tap to Next (`6`). A separately requested fresh
  touch read returned `6`; all other bindings were unchanged.
- Result: the narrowly scoped touch mapping is confirmed and restored.

### ANC hold cycle

- The checkout originally coupled hold-cycle read support and write permission.
  A local split gate now permits the Pro 2 read query while keeping its write
  explicitly unverified and unavailable.
- First Nord-shaped query attempt returned a frame that failed the strict
  four-byte hold-mask parser (`device returned malformed hold cycle`). The
  controller invalidated the logical session; no write was sent. The next
  read captured the response shape without recording the Bluetooth address.
- Repeated read captured `response=0x810c:0002010600`: the established mask is
  `0x06` (ANC + Transparency), followed by one additional zero byte on Pro 2.
- The local parser now accepts only that exact trailing-zero variant for product
  `062014`; hold-cycle writes remain explicitly disabled.
- Phone changed the cycle from ANC + Transparency to ANC + Off. A fresh read
  returned mask `0x03`, decoded as ANC + Off, with `writable=false`.
- Phone restored ANC + Transparency. A fresh read returned mask `0x06`; the
  mapping and restoration are confirmed.
- The detached profile may now enable only the hold-cycle write gate for an
  isolated `0x06 -> 0x03 -> 0x06` plugin trial.

Checkout plugin write trial:

- Plugin changed the cycle from ANC + Transparency (`0x06`) to ANC + Off
  (`0x03`). Its internal readback and a separately requested read both returned
  ANC + Off.
- Plugin restored ANC + Transparency (`0x06`). A separately requested fresh
  read returned ANC + Transparency.
- Result: Pro 2 hold-cycle write and restoration confirmed, including its
  model-specific trailing-zero read response.

### BassWave

- The existing bass status query succeeds on Pro 2 and returns `min=-5`,
  `max=5`, `level=2`.
- The feature-switch query independently reports `bass_engine=true`.
- Bass-level writes remain disabled pending a phone-app level change/read/restore
  trial.
- Phone changed BassWave from `+2` to `+1`. A fresh bass-status read returned
  `level=1` with the same `min=-5`, `max=5` range.
- Phone restored BassWave to `+2`. A fresh read returned `level=2` with the
  same range; the level mapping and restoration are confirmed.
- Only the `bass_engine` capability may now be added for an isolated checkout
  write trial; Find My Earbuds remains unavailable.
- First generic plugin write set level `+1` and returned status `0`, but the
  required independent read exposed that its Nord-derived payload also changed
  the stored range from `-5..5` to `-10..10`. This trial is not accepted as a
  safe Pro 2 write.
- The local writer is being corrected to use the measured Pro 2 range bytes
  (`-5,+5`) before restoring both range and level (`-5..5`, `+2`).
- Corrected restore used range bytes `fb 05`; a fresh read confirmed the exact
  original state `min=-5`, `max=5`, `level=2`.
- Corrected plugin trial then changed `+2 -> +1`; a separate fresh read returned
  `min=-5`, `max=5`, `level=1` (range preserved).
- Corrected plugin restore changed `+1 -> +2`; a separate fresh read returned
  `min=-5`, `max=5`, `level=2`.
- Result: BassWave write is confirmed only with the Pro 2-specific `-5..5`
  payload; the generic `-10..10` payload must not be used.

### Find My Earbuds

- The PR exposes only a start/stop write and tracks its own state; it has no
  device query that can provide an independent fresh readback.
- Plugin write remains unavailable pending Pro 2 phone-app evidence. Even with
  phone evidence, the lack of protocol readback must be called out before any
  plugin write is considered.
- With both buds removed from the user's ears, the phone app started a left-bud
  find tone and the user confirmed it was audible. The app's Stop action ended
  the tone.
- This confirms the Pro 2 feature exists and the phone workflow is reversible,
  but does not establish that PR #6's generic boolean `0x0400` command matches
  the Pro 2 app command. Because there is no independent status query/fresh
  readback, the plugin Find write remains disabled.
